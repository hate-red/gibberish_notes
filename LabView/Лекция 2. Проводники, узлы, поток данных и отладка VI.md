## Узлы блок-диаграмм
Функции, ВПП и структуры являются исполняемыми узлами. Узел начинает работу,  когда на его входах доступны необходимые данные.

>**Важно**: Оценивать не только "как сделать", но и как решение поведет себя при ошибке, остановке, изменении входных данных

## Проводники
Проводник переносит данные между терминалами. Цвет и толщина помогают распознавать тип данных, разветвление передает одно значение нескольким потребителям.

Если на выходе и на входе в терминал разный тип данных, то broken wire - несогласованность типов.

>**Самая частая ошибка начинающего разработчика**: несоблюдение типов входа и выхода
## Потоки данных
Порядок определяется зависимостями по данным, а не расположением объектов слева направо.

Параллелизм - независимые ветви блок-диаграмм могут работать одновременно.
#### Полиморфные функции
Одна функция может принимать разные типы данных. Снижение количества специальных функций упрощает работу,  делает код компактнее, но требует контроля типов и преобразований.

## Отладка
### Средства отладки
1. Run 
2. Abort - остановить немедленно 
3. Probe - показывает значения/информацию, проходящую по проводу
	- Только после выполнения (Т.к. значения сохраняются после 1 успешного выполнения)
	- Для сложных диаграмм
	- Потребление памяти. Сохранение значений для всех проводников увеличивает потребление памяти
	- Для ВПП. По умолчанию функция действует только на текущий ВП. Чтобы сохранить значения во всех вложенных ВПП, нужно включать ее рекурсивно   
4. Breakpoint
5. Highlight Execution - анимация потока данных
6. Пошаговое выполнение

### Поиск ошибки
- Broken wire
- Error List
- Проверка входов
- Проверка Probes на ключевых проводниках
- Исправление

>**Первое правило отладки**: отладка должна воспроизводиться. Для этого нужно фиксировать входные данные, ожидаемый результат и найденную причину.
