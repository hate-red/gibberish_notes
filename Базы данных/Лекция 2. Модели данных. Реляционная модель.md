# Лекция 2. Модели данных. Реляционная модель
## Модель данных
### Компоненты
1. Структуры (таблицы, отношения, схемы)
2. Операции (что с ними можно делать)
3. Ограничения целостности (допустимые состояния)

Модель данных убирает дублирование и противоречия, неясность обязательных данных, сложность поиска и изменения, отсутствие правил для связанных объектов.

### Модель ANSI
1. Верхний уровень
   >Пользовательские представления и приложения
2. Концептуальный уровень
   >Единая логическая модель всей БД
3. Внутренний уровень
   >Физическое хранение данных
   
### Независимость данных
- Логическая независимость
- Физическая независимость

## Реляционная модель
### Преимущества
1. Связь через ключи
2. Формальная основа
3. Декларативные запросы
4. Физическая независимость

### Этапы проектирования
1. Анализ
2. ER-модель
3. Реляционная схема
4. Реализация

### ER-модель
1. Сущность
   >Что существует?
2. Атрибут
   >Какое свойство храниться?
3. Ключ
   >Как идентифицировать
4. Связь
   >Как соотносятся?
5. Кардинальность
   >Сколько объектов существует?
6. Слабая сущность
   >Может ли объект существовать без владельца?
   
### Виды связей
1. 1 : 1 (один к одному)
2. 1 : N (один ко многим)
3. M : N (многие ко многим)

### Основные понятия
1. Отношение (таблица, набор кортежей заданный на атрибутах)
2. Кортеж (строка таблицы)
3. Атрибут (свойство сущности)
4. Домен (множество допустимых значений атрибута)

### Внешний ключ
Внешний ключ выражает связь и требует, чтобы ненулевое значение ссылки существовало в родительской таблице.

### Свойства отношения
1. Нет логического порядка кортежей
2. Кортежи уникальны
3. Нет логического порядка атрибутов
4. Значения атомарны (каждое значение принадлежит своему домену и неделимо)
